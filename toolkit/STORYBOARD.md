# Storyboard and render

A piece moves from plan to board to approval to render through one shared generator, so the frames Umer approves on the canvas run the same element code, the same timings and the same sounds as the video HyperFrames writes. Nothing renders until he says the board is approved.

## The plan

`scene-plan.json` follows `schema/scene-plan.schema.json`: the style slug, a `mode`, a title, the format, the duration, the voice-over with its word timings from `tts.py` when the style speaks, the music with its beat grid when it has one, and the scenes that tile the piece. Each scene names the feeling it must land, its voice-over line (empty in a music-only piece), a layout (center, stack, split, free or full, or a `.me-stage.layout-<name>` rule in the style's `tokens.css`) and its moves. A move names a library element, a target node and a start time given in seconds, as `word:<index>` on a voice-over word, or as `beat:<index>` or `downbeat:<index>` on the music's grid, each with an optional offset (`word:12-0.08` leads the word by 80ms, `beat:8+0.04` trails the beat by 40ms).

The voice-over is optional, because some styles are cut to music alone. Such a plan leaves `vo` out, or sets its `audio` to null and its `words` to an empty list, and times its moves in seconds or on the beat grid, since a `word:` reference with no words to point at fails the gate. The grid is a JSON file of the form `{"beats": [t...], "downbeats": [t...]}` in seconds from the start of the piece, named by `music.beats` in the plan (a path beside the plan, or the object inline) or passed as `--beats <json>` to any of the three scripts, where the flag wins. `music.clip` names the bed, which stands in when the sound plan carries no music of its own, at `music.gain_db` (0 dB when unset).

Media lives in move props as paths: any prop under the keys `src`, `plate`, `bg`, `fg`, `image`, `bgClean`, `poster`, `video`, `still` or `mask`, and any string prop at any depth ending in `.png`, `.jpg`, `.jpeg`, `.webp`, `.svg`, `.avif`, `.gif`, `.mp4`, `.webm` or `.mov`. A relative path resolves beside the plan first and then in the style folder, and the same holds for image `url()`s in the style's `tokens.css`, `fonts.css` and library elements (an element's own folder comes first for its urls) and for any string in `tokens.json` ending in a media extension. A reference that resolves nowhere draws a warning and is left as written, so a file someone placed beside the board by hand keeps working.

`mode` is `piece` unless the plan says `replica`. A replica rebuilds the source itself to prove the moves and the layering match, and is the only plan allowed to use the source's own frames, which `imagery.py plates-from-source` writes as `calibration-only-shot-NN.png` under a `CALIBRATION-ONLY.json` marker. In a piece, any referenced file whose name or any folder on whose path starts with `calibration-only-`, or which sits anywhere below a folder holding that marker, closes the gate, and symlinks are followed so a link cannot carry a source frame past it. The first move on a target renders it and later moves on that target animate the same node. A move the source never showed is marked `novel` with a `grammar_note`, and it runs either as an element written beside the plan in `library/<name>.html` or as `props.tweens` built from the style's primitives, which the validator checks against the envelopes in the style's `grammar.json` (each entry follows `schema/move.schema.json`). A move may carry `sfx: false` to silence its sound or an `sfx` object to override it.

```
node toolkit/validate-plan.mjs <plan.json> [--style-dir <dir>] [--beats <json>] [--sfx <sfx-plan.json>] [--json]
```

The validator fails a move that is neither in the library nor marked novel with a note, a time outside its scene, a word index that does not exist or a word reference in a plan with no words, a beat reference with no grid or past its end, a malformed grid, overlapping scenes, a composed tween outside its envelope or on a property the source never animates, a missing audio, music or clip file, and a calibration-only file in a piece. `--sfx` adds the sound plan's clips to what the calibration guard reads. It warns on media that resolves nowhere and on a plan with neither a voice-over nor a music clip. `--style-dir` points at a style outside `skills/<slug>-motion`, which is how the throwaway test style under `work/test-style` runs.

## The board

```
node toolkit/storyboard.mjs <plan.json> --out work/<piece>/board --name <piece> \
  [--sfx work/<piece>/sfx-plan.json] [--style-dir <dir>] [--beats <json>] --register
```

This writes `01-<id>.html` per scene, `board.json`, a local `gsap.min.js` and every referenced image or video under `assets/plates/`, named `<folder>-<stem>-<first 8 hex of the content's sha256><ext>` (so `matte-05/bg.png` becomes `matte-05-bg-25bd68ff.png`) with the props and urls rewritten to that relative path. The name changes only when the bytes do, so a re-run copies nothing new and the canvas reloads only frames whose plate changed, and files the plan no longer references are pruned from that folder. Each frame inlines the style's fonts, tokens and the library elements its moves use, builds a paused GSAP timeline through each element's `animate()` and registers it as `window.__timelines = { main: tl }`, which the canvas plays and scrubs. Every element carrying a move has `data-move` and `data-target`, novel ones add `data-novel`, and the scene root has `data-scene`, so a pinned comment names the move it means. A review overlay docked at the foot of each frame shows the feeling, the voice-over line, a ruler with the words (or, in a music-only piece, the beats, with downbeats drawn taller in yellow), one bar per move spanning the tweens it actually placed (blue for signature, hatched amber for novel), the sound markers with class and clip, and a playhead that follows the scrubber. The pill or the O key hides it, `?clean` drops it for stills, and it never reaches a render. `board.json` notes repeat the feeling, the line, the beats, the moves and the sounds for each frame, and the board records the mode, the voice-over, the bed, the grid and which source file each plate came from. `--force` still draws a board whose gate is closed, a piece holding calibration-only plates included, and says so in the log, because the canvas is a private review surface and the build refuses the same plan outright.

`--register` runs `canvas add` and prints the URL and the monitor to arm, `~/storyboard-canvas/bin/canvas watch <piece>` with a timeout of 1800000, re-armed whenever it expires while review continues. Load the `storyboard-canvas` skill before reviewing.

## Handling comments

A comment arrives naming the frame, the element's `data-move` and target, and the paused time. Read the timeline at that time, then fix the source: the plan for timing, props or sound, the style's library element or tokens for the move itself. Re-run `storyboard.mjs` with the same arguments, which rewrites only the frames whose content changed and keeps the canvas's `.canvas/` comment state, so those frames hot-reload in place and nothing asks him to refresh. Patching a frame file by hand would let the board drift from what the composition renders, so the frame is always regenerated. Close each comment with `canvas resolve <piece>#<n> "the slam on fewer now lands 60ms earlier with a harder overshoot"`, written in his terms. When a comment could mean two things, ask with `canvas reply <piece>#<n> "question"` rather than guessing.

## The composition and the render

Once he approves the board:

```
node toolkit/build-composition.mjs <plan.json> --out work/<piece>/project [--sfx <sfx-plan.json>] [--style-dir <dir>] [--beats <json>]
toolkit/render.sh work/<piece>/project work/<piece>/out.mp4
```

The build refuses a plan that fails the gate, a novel move not yet built and any sound or music file not on disk, and then checks the calibration guard a second time over exactly the files it is about to copy or inline (voice, bed, every effect, every plate, every element, the grid), so a piece cannot reach a render with a source frame in it even when called from code that skipped the gate. It writes `index.html` with every scene as a clip on one paused timeline at `window.__timelines["main"]`, the voice-over as `<audio id="vo">` when the plan has one, the music bed with its level as a gain stage whose automation ducks it by `duck_db_under_vo` across each spoken phrase and fades the tail, and each sound effect as its own clip at its planned time and gain. The bed is the sound plan's music when it has one and `music.clip` otherwise. With no voice-over the build renders without a voice clip, skips ducking so the lane only fades the tail, treats the bed as the spine the piece is timed against, and warns when the bed runs shorter than the piece because the tail would then be silent. Plates are copied to `assets/plates/` under the same names the board used. A panned effect is rendered to a derived stereo file first, since HyperFrames has no pan control. `build.json` records what was built from what, including the mode, the voice-over, the bed and where it came from, the grid and each plate's source file.

`render.sh` runs `npx hyperframes@0.8.101` lint, then check, then render at high quality, stopping on any error before spending render time. `STRICT=1` makes check fail on warnings too and `QUALITY=draft` speeds iteration. It then confirms the video's duration matches the root `data-duration` to within one frame and reports the audio streams.
