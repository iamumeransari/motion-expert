Merging the three block kits into one runtime (library/_runtime, 2.0.0) and moving the source content out of the skill, the re-proofs could not be held to 0.001 against the published scores, for two reasons that had nothing to do with the blocks. toolkit/measure/common.py changed its colour-matrix handling at 13:26, after several baselines were scored, so a byte-identical render of the title cards moved from 0.971 to 0.984 on one shot; and renders that load image sequences are not bit-repeatable, so an untouched baseline project re-rendered drifts by up to 0.009 in relative flow. The proof standard is now: re-score the unchanged baseline with the current compare.py, report bit-identical renders as such, and otherwise report the delta against that re-score with a fresh base re-render as the noise floor. Separately, the larger runtime script shifts text rasterization by a deterministic sub-pixel amount on a few blocks (about 53 to 60 dB PSNR over text layers, identical DOM and styles, scores within the floor); endcard-typeon's layout latch on document.fonts is the visible case. Two other rules came out of the pass: block code reaches shared helpers only through window.__esRuntime, never a pasted copy, and general-mode fonts and colours come from tokens or props so a style directory with another tokens.css re-skins every block.
